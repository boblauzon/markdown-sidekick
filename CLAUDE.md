# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Markdown Sidekick — a Windows desktop app (Python 3.10+, Tkinter) that converts documents/images/scanned PDFs/audio to Markdown. Wraps Microsoft `markitdown` with local OCR (RapidOCR), local transcription (faster-whisper), a post-conversion cleanup pipeline, and an MCP server. Freeware by VibeProSoft; MIT-licensed code, but **avoid GPL/AGPL dependencies** (pypdfium2 was chosen over PyMuPDF, MinerU is endpoint-only not bundled, Marker was rejected — keep it that way).

## Commands

All commands use the project venv; there is no global Python assumption.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt   # setup (or run setup.bat)
.venv\Scripts\python.exe app.py                               # launch the GUI
.venv\Scripts\python.exe app.py --selftest                    # end-to-end pipeline check, JSON report to %TEMP%, exit 0/1
.venv\Scripts\python.exe app.py --mcp                         # MCP server over stdio (also: run_mcp.py)
.venv\Scripts\python.exe -m markdown_sidekick.cli convert x.pdf --split-chapters   # headless CLI
.venv\Scripts\python.exe -m markdown_sidekick.cli diagnostics                        # digest of the error log + debug traces
.venv\Scripts\python.exe -m pytest tests/ -q                  # run tests
.venv\Scripts\python.exe -m pytest tests/test_cleanup.py -k toc -q    # single test / pattern
.venv\Scripts\pyinstaller.exe MarkdownSidekick.spec --noconfirm       # build standalone exe (~4 min)
ISCC.exe installer\MarkdownSidekick.iss                               # build the installer from dist\ (~2 min; Inno Setup 6)
```

- `pytest` is a dev-only dependency — it is deliberately **not** in `requirements.txt`; install it into the venv if missing.
- Don't feed Python source containing backslash escapes (`\n`, `\d`) through a Bash heredoc — it gets mangled; use the Edit tool (or Write a patch script to a file and run that).
- `--debug` on any entry point (`app.py --debug`, `cli convert … --debug`) turns on debug mode for that run.
- After building, run the exe from `dist\MarkdownSidekick\`, never `build\` (the build\ copy has no runtime and fails with "Failed to load Python DLL"). Validate frozen builds with `dist\MarkdownSidekick\MarkdownSidekick.exe --selftest`.

## Architecture

`src/` layout; the core is UI-agnostic and reused by four front-ends: the Tkinter GUI (`ui.py`), the MCP server (`mcp_server.py`), the headless CLI (`cli.py`), and scripts/tests.

**AI-friendly export layer** (applies at *save/export* time, never to preview/copy): `export.py` (YAML front matter incl. PDF-sourced `title`/`author` and `image_count`, chapter splitting on `#` headings with a book-mode filter — when ≥3 `# Chapter/Part N` headings exist only those split, because stray unfenced code comments also look like H1s — plus index.md/manifest.json; lead text before the first split heading is `00-front-matter.md` so chapter N lands in file N), `quality.py` (artifact scanner + 0-100 score + token estimate; flags prepress residue and doubled shadow text), `figures.py` (pypdfium2 image extraction to `images/` as `fig_p{page}_{k}`, ≥120 px on BOTH sides, inside the TrimBox, deduped by stream hash; RGB/grey JPEGs copied verbatim, CMYK and everything else decoded (convert the PIL image BEFORE closing the bitmap — `to_pil()` shares its memory); in a scan-dominated PDF (≥50% of pages covered ≥85% by one image) page-covering images are the pages, not figures, and are skipped; `<!-- figure N.K -->` markers are replaced in place, else anchor/trailing-section fallback — `page_images()` is the ONE enumerator both the markers and the extractor use, so keys always agree), `polish.py` (opt-in local-AI passes: a repair pass with a size guardrail — a response outside 0.7–1.3× the chunk is discarded — figure captions, and `summarize_markdown`, a 2–3 sentence document summary that export writes as `summary:` front matter / `book_summary:` on book parts; it sees a curated view — title, `#`/`##` outline, and an excerpt starting at the Introduction/Preface heading, never cover/TOC — asks for JSON via a schema with an `insufficient_content` escape hatch (retried once in plain text if the server rejects structured output), and drops any reply that is a refusal/chat/meta-commentary or echoes slugs; never truncated mid-sentence). Tests build real PDFs via `tests/pdfgen.py` (`make_pdf` simple; `make_layout_pdf` places Helvetica/Courier runs and images at explicit positions, with TrimBox and nested bookmarks — draw order is the content-stream order, so tests can make stream order ≠ reading order).

The output shape is chosen in the GUI's export bar and persisted as `Settings.export_style` (`"single"` / `"chapters"` / `"ai"`) + `ai_target`. `"ai"` uses `export.split_for_ai` with a per-platform budget from `export.AI_TARGETS`; its guarantees (encoded in `tests/test_export_quality.py`) are: the budget is a **hard cap** checked *before* a boundary is passed, fences are **never** split, unbalanced fences (a real OCR artifact) disable fence tracking rather than disable splitting, and only a single indivisible fenced block may exceed the budget. Small consecutive sections are then packed up to the budget (parts titled "First – Last"; a part breaks only at a section boundary, a hard split never ends a chunk on a heading, and a heading-only section carries forward into the next part) — `split_for_ai(pack=False)` keeps one entry per chapter for MCP navigation (`convert_outline`/`convert_section`, whose indices must agree). Only a part that is purely front matter is numbered `00-`. `AI_TARGETS["Claude"]` deliberately aliases `DEFAULT_MAX_TOKENS` — they are one number, don't let them drift. Targets in `NOTEBOOK_TARGETS` ("Gemini Notebook", formerly NotebookLM) are not context budgets: each file becomes a retrievable *source*, so `export_book(notebook=True)` uses `split_for_notebook` — one source per chapter, packed (with the smallest budget that works, via binary search over `_pack`) only past `NOTEBOOK_MAX_SOURCES`; the target's value is the per-source hard cap, 120k est. tokens = 480k chars, which can't exceed the 500k-words-per-source limit in any script (CJK counts each char as a word). Notebook output swaps YAML for a readable one-line header (a `converted:` date gets cited as the book's date), prefixes filenames with the book's short slug, reduces image links to `[Figure …]` text outside code, and writes no index.md/manifest.json — every file in the folder is a source to upload.

**Conversion routing** (`converter.py::ConversionEngine.convert_file`) — tries specialised engines in order, each wrapped in try/except that falls through to the next; `convert_file` never raises, errors land on `ConversionResult.error`:

1. image file + OCR enabled → RapidOCR (`engine="ocr"`)
2. PDF + MinerU endpoint configured → remote MinerU (`"mineru"`)
3. PDF that triages as scanned (`ocr.analyze_pdf`: low text layer + page-dominating image **or** ≥12 vector paths) → `pdflayout` with OCR as the per-page text provider for the scanned pages (`"ocr+text"`, always anchored)
4. digital PDF + `pdf_layout` (default on) → `pdflayout.extract_markdown` (`"pdflayout"`); <50 chars of body falls through
5. audio → faster-whisper (`"whisper"`)
6. everything else (and PDFs with `pdf_layout` off) → markitdown (`"markitdown"`; `"pdftext"` when anchors are on)

**PDF layout engine** (`pdflayout.py`, pypdfium2 only — markitdown's PDF path row-clusters words across the whole page, slicing multi-column prose into tables). Per page: clip chars to the TrimBox (slugs, job tickets and a spread's facing page live outside it); dedupe glyphs drawn on top of an identical glyph (shadow/fake-bold) — but NOT neighbours in the same text object, because pdfium gives ligature components (`f`,`i` of "fi") one shared box; pdfium itself already drops an *identical* repeated text object, so real shadow plates reach us only when chunked differently; segments split at >0.8×height gaps; recursive XY-cut, columns (full-height whitespace channels) before rows, row cut at the widest gap above median+0.3h. Guards on a column cut: a numeric grid becomes a Markdown table (columns from the x-projection of WORDS — cells sit closer than a segment gap), a page-ref column beside text reads row-wise (TOC), narrow short labels aligned with right-hand rows read row-wise (key/value). Running headers/folios are removed geometrically, only from the outermost two baselines within 12% of the page edge (top and bottom picked independently): text with real letters recurring on ≥3 pages; a bare number ONLY when it matches the folio offset learned from the outermost lines (arabic and roman separately, indexed by PHYSICAL page so OCR'd pages don't shift it); an outermost ≤5-word line carrying the page's own folio number. Never drop a bare number just for sitting in the margin — list items ("2."), table values and index refs live there too. Paragraph reflow uses a "would the next word have fit?" test. Fixed-pitch runs (font NAME regex — Packt's Consolas has no FixedPitch flag) become plain fences with indentation rebuilt from x positions (cleanup's `repair_fences` labels them); disabled when mono is >35% of the doc. Bookmarks → headings at `#` for the shallowest level with ≥2 non-front-matter entries (Cover/Title/Copyright/Contents… are skipped so they fall into front matter; "by category" duplicate subtrees are dropped); a heading replaces the block that prints its title. Doc-level: control chars / pdfium's U+0000 (kept as a \x1a placeholder) are lost ligatures, resolved per word against the doc vocabulary + `_SEED_WORDS` (whole word, else the longest known word spanning the ligature — "undi?erentiated" holds "different"), else by the code's majority vote; codes are NOT document-wide — every font subset picks its own (one Quarto book used ~40 codes for "ff"), so a second round re-resolves against words fixed in the first; `\x02` is pdfium's line-end hyphen, resolved (compound kept only if the doc spells it hyphenated mid-line; after a digit the hyphen always stays — "24-hour"). Paragraphs cut at a column/page break rejoin when the next block starts lowercase, or — capitalised — only when the previous block ends on an article/"of"/conjunction AND the next completes a sentence and isn't a caption (figure labels often sit between the halves). Title: metadata (filenames rejected) → Title-bookmark page → copyright page (LoC CIP "Title: … / Author.", or the title lines above "Copyright ©") → the first text page if it reads as a title page; block `h` is per paragraph, so a subtitle doesn't inherit its title's size.

**Cleanup pipeline** (`cleanup.py::clean_markdown`) — ~10 independent, toggleable passes. Invariants:

- *Conservative by design*: every heuristic favours false negatives; a pass must never delete real content. Removal is gated (min repeat counts, cluster sizes, both-signals rules) — keep that bar when adding passes.
- *Fenced code is exempt* from every line-deleting pass (page noise, both TOC passes, boilerplate, prepress, shadow): a REPL's bare `42` is output, not a folio, and a dropped fence marker unbalances the rest of the document.
- *Engine-aware*: callers pass `engine=result.engine`; page-noise stripping is skipped for `pdflayout` output, which already removed furniture geometrically — on it the text-pattern pass only deleted content ("Step 1" labels, citations, a chart's years).
- *Pass order matters*: shadow de-doubling runs **before** prepress stripping (doubled job tickets "JJoobb::" only match once repaired), and both run first; chapter titles are harvested **before** the TOC (their source) is stripped; page-noise/boilerplate removal runs **before** code fencing (running headers split listings); paragraph joining runs **after** fencing (fenced code is exempt from joining); U+FFFD scrubbing runs **after** TOC stripping (the TOC detector keys on FFFD leader runs).
- *Prepress pass* (`strip_prepress`): removes slug TOKENS and drops a line only when the residue is junk (≤1 real word; table cells: 0) — slugs are often merged with real text in markitdown output. STRONG tokens (dated `.indd` stamps, job tickets, DTP stamps, Fogra tags) go anywhere; an undated `.indd N` only with an underscored InDesign job name, other slug evidence on the line, or alone on its line ("grid.indd 2 times" in prose survives); operator tags "(RAY)/(Ray)/(Text)" are CASE-SENSITIVE and only removed beside a strong token or on a tags-only line; lines that look like code are never touched (`def show(text):`). The `.indd` filename is matched BACKWARDS in a 120-char window (a forward optional-prefix regex backtracked quadratically: 51 s/book), allowing words only before the underscored name. Gated per document (one dated/stand-alone stamp, or ≥2 weaker markers). *Shadow pass*: a doubled run is repaired only if it contains a word-like token (vowel + consonant, not nucleotides) — "XXXX", "AATT CCGG" survive. Validated on the 18-book Quarto corpus (MD2): 9,147 slug hits → 0, doubled words 15,466 → 208 (the rest: multi-layer type specimens in one book).

The passes were tuned against a real 25-book PDF-conversion corpus; `tests/test_cleanup.py` encodes those artifact shapes — run it after any cleanup change. Fence language labels come from `_guess_language` (content scoring; returns `""` plain fence when ambiguous — an honest plain fence beats a wrong label). `CleanupStats` fields must all be non-negative int counters: `total_fixes`/`changed` derive from `dataclasses.fields`, so a new pass's counter is picked up automatically but a non-counter field would poison the sum.

**Errors and diagnostics** (`errors.py`, `debuglog.py`, `diagnostics.py`, `errorview.py`) — two tiers, both under `%LOCALAPPDATA%\MarkdownSidekick\logs` (`MARKDOWN_SIDEKICK_LOG_DIR` overrides; `tests/conftest.py` sets it so tests never touch the real log):

- *Every error has a code* (`errors.CATALOG`, `MS-<area><nn>`: 1xx conversion, 2xx saving, 3xx local AI, 4xx figures, 5xx settings, 6xx system, 9xx unexpected) pairing a plain-language title with a next step and an optional `action` key that the GUI renders as a one-click button (`ui._error_handlers`). `errors.report(code, exc=…)` is the ONE way to raise an error to the user: it writes `errors.jsonl` (always on, rotated) with a 6-hex ref + traceback and returns the `Incident` to show. Never add a bare `except Exception: pass` or a raw `messagebox.showerror` — report a code. New code ⇒ add the spec, and `tests/test_error_codes.py` fails until it is in USERGUIDE.md's *Error codes* tables (`python -m markdown_sidekick.errors` prints them from the catalog — paste over the old tables). Next-step wording must read right in the CLI/MCP too (no "click …").
- *`convert_file` still never raises*, but no fallback is silent: each failed route lands in `failures`, and `_diagnose` turns them into `result.error_code`/`error_ref` (the specialised route's failure is the reported cause — a whisper download failure, not markitdown's "no text") or, when a later route succeeded, `result.warnings` (MS-114/120–125). Front-ends show warnings (GUI: ⚠ row + notice bar; CLI: `warn [MS-…]`; MCP: a note).
- *GUI surfaces*: blocking failures → `_show_error` (modal, rate-limited per code); non-blocking → `_show_notice` (the bar above the progress line; `owner=path` ties it to a file); a failed file's message + fix/Retry/Copy-details buttons live in the preview. `report_callback_exception` and the worker's `try/finally` (always posts `done`; unreached files become MS-902 failures, never pending — pending would re-run the crash) mean an exception can't leave the app silently broken or stuck busy.
- *Debug mode* (`Settings.debug_mode`, `--debug`, `MARKDOWN_SIDEKICK_DEBUG=1`) adds `logs/sessions/<stamp>-<pid>-<source>/events.jsonl`: `debuglog.event/span/context` calls are a flag check when off, so instrument freely — but only via those (never stdout: MCP). It records routes, PDF triage, per-page timing, `pdflayout.done` (phases, per-page block kinds, title source), `cleanup.done` (per pass: ms, lines gone, samples), quality, export, local-AI calls, UI actions, `ui.stall` (Tk tick ≥1 s late), and keeps raw/cleaned snapshots; `faulthandler.log` gets native crashes and a stack dump when the UI thread is silent 20 s. `debuglog.py`/`errors.py` are stdlib-only (settings and export import them).
- **To assess a user's logs**: `.venv\Scripts\python.exe -m markdown_sidekick.cli diagnostics [--sessions N]` prints a digest (errors by code → failed routes → stalls → slowest steps → quality, flagging any cleanup pass that removed ≥5% of a document's lines); for a shared report zip, read `summary.md` first, then `logs/…/events.jsonl` and diff `snapshots/*.raw.md` against `*.cleaned.md`.

**Threading**: the GUI runs conversion on a worker thread; progress callbacks (`on_progress`, `on_subprogress`) must stay thread-safe. Cleanup + quality assessment are precomputed per file inside the worker's `on_progress` (selecting a big book must never stall the Tk thread — misses show a watch cursor); Tk variables (Clean/OCR toggles) are read on the main thread *before* the worker starts and passed in, never read from the worker. The MCP server serializes conversions with a lock because the OCR/whisper model singletons and the stdout redirect are not thread-safe.

**MCP server** (`mcp_server.py`): stdout is reserved for JSON-RPC — logging goes to stderr and conversion runs inside `redirect_stdout(sys.stderr)`. The `FASTMCP_*` env vars are set **before** importing fastmcp (`FASTMCP_CHECK_FOR_UPDATES` must be `off`, not `false` — it's a Literal and `false` crashes the import).

**Settings** (`settings.py`): dataclass persisted to `%LOCALAPPDATA%\MarkdownSidekick\settings.json`; load is fully tolerant of junk — every field is validated in `normalize()` (enum-like strings get membership checks, e.g. `ai_target` against `export.AI_TARGETS`). When renaming/removing a persisted key, add a migration in `load()` (see the legacy `split_chapters` → `export_style` mapping) — unknown keys are silently filtered, so without one the user's preference is lost. `settings.py` imports `export.py` at module level; that's fine only because `export.py` is stdlib-only — keep it that way. Whisper models are materialised as real file copies under the same dir (`local_dir=`, not the HF symlink cache — Windows symlink privilege issue).

**Startup time**: RapidOCR, faster-whisper, and fastmcp are lazy-imported. Don't add module-level imports of heavy libraries to anything `ui.py` pulls in at startup.

**Preview** (`mdrender.py`): a deliberate CommonMark *subset* renderer for the Tk Text widget — underscore emphasis is intentionally unsupported (snake_case would misrender), and links inside `**bold**` are not parsed. Raw Markdown remains the source of truth for copy/save. The preview *displays* at most `ui.PREVIEW_MAX_CHARS` (rendering costs ~250ms/MB on messy text); copy/save always use the full document.

## Packaging touchpoints

Adding a data file or a new heavy dependency usually means touching three places: `pyproject.toml` (package-data / dependencies), `MarkdownSidekick.spec` (datas / collect_all), and `app.py --selftest` if it's pipeline-critical (its `error_codes` and `debug_trace` checks prove the error log and debug mode work in a frozen build). RapidOCR v3 downloads its ONNX models into site-packages on first use — run one OCR (e.g. `app.py --selftest`) in the build venv **before** PyInstaller so `collect_all("rapidocr")` bundles them; the frozen selftest's `image_ocr` check proves it worked. OCR device selection: `Settings.ocr_device` (auto/cpu/gpu) — "auto" resolves DirectML from `onnxruntime.get_available_providers()` in `ocr.py` because RapidOCR's own default silently stays on CPU. `USERGUIDE.md` ships inside the package (loaded via `importlib.resources`) — keep its links unwrapped by bold.
